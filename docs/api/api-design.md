# API design conventions

## Basics

- Base path: `/api/v1`. JSON over HTTPS. OpenAPI generated by FastAPI; the frontend client is generated from it.
- Resource-oriented, plural nouns; `kebab-case` paths, `snake_case` JSON fields.
- Authentication: `Authorization: Bearer <access_token>`; refresh via cookie.
- Time: ISO 8601 UTC. IDs: UUID strings. Titles also have `slug`.

## Pagination

Cursor-based:

```
GET /api/v1/titles?limit=24&cursor=eyJ...
-> { "items": [...], "next_cursor": "eyJ..." | null }
```

`limit` default 24, max 100.

## Filtering and sorting

`?genre=drama&language=en&year_from=2020&sort=-published_at`. Whitelist sortable fields.

## Errors (RFC 9457)

```json
{
  "type": "https://qorvexa.app/problems/validation-error",
  "title": "Validation failed",
  "status": 422,
  "detail": "The request body is invalid.",
  "errors": [{ "field": "email", "message": "Invalid email address" }],
  "request_id": "01J..."
}
```

Status codes: 200/201/204, 400, 401, 403, 404, 409, 422, 429 (with `Retry-After`), 5xx.

## Idempotency and concurrency

- `PUT` for idempotent replacements (e.g. progress upsert).
- `Idempotency-Key` header supported on upload-session creation.
- ETag / `If-None-Match` for public catalog GETs.

## Rate limits (initial)

| Scope | Limit |
|---|---|
| `/auth/login` | 5/min per IP+identifier |
| `/auth/register`, reset | 3/min per IP |
| Catalog reads | 120/min per IP |
| Progress writes | 30/min per profile |
| Admin | 60/min per user |

## Versioning

Breaking changes go in `/api/v2`. Additive changes (new optional fields) stay in v1. Deprecations are announced in the changelog with a removal date.

## Webhooks (inbound)

`POST /api/v1/webhooks/{provider}`: verify signature, store event (unique by event ID), respond 2xx quickly, process in a worker.
